# 3.3 Quản Lý Kết Nối Mạng (Connection Pooling, Keep-Alive & I/O Optimization)

## 1. Cơ Chế HTTP Keep-Alive Tại Tầng Nginx
* **Thông số `keepalive_timeout 65s`:** Cho phép trình duyệt sinh viên tái sử dụng kênh TCP socket đã mở cho nhiều request liên tiếp (tải danh mục, gửi yêu cầu đăng ký, thực hiện polling).
* **Thông số `worker_connections 10240`:** Đảm bảo mỗi Nginx worker tiến trình có đủ file descriptors để xử lý hàng ngàn kết nối đồng thời từ 3.000 sinh viên.

## 2. Quản Lý Connection Pooling (Redis, RabbitMQ & PostgreSQL)

### 2.1. Redis Connection Pool
* Mỗi FastAPI worker duy trì một `ConnectionPool` với kích thước `max_connections = 50`.
* Tổng kết nối Redis từ 2 App Nodes: $\approx 100 - 200$ connections. Redis hỗ trợ mặc định tới 10.000 connections, do đó kết nối mạng luôn thông suốt.

### 2.2. PostgreSQL Connection Pool
* Cơ sở dữ liệu quan hệ PostgreSQL gặp hiện tượng nghẽn nghiêm trọng (Context Switching) nếu số lượng active connections vượt quá 100 - 200.
* **Chiến lược kiểm soát:**
  1. API Server **không kết nối trực tiếp đến PostgreSQL** trong luồng ghi danh (tất cả ghi nhận đi qua RabbitMQ).
  2. Chỉ có **Registration Worker** kết nối đến PostgreSQL với pool size cố định $10 - 20$ kết nối.
  3. Nhờ đó, PostgreSQL hoạt động ở trạng thái an toàn tuyệt đối, loại bỏ 100% nguy cơ cạn kiệt connection pool.
