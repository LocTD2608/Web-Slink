# 1.2 Chỉ Số Hiệu Năng & Mục Tiêu SLA/SLO (Service Level Agreement / Objective)

## 1. Định Nghĩa SLA và SLO của Hệ Thống

| Mục tiêu (Objective) | Phân vị / Chỉ số đo lường | Tiêu chuẩn SLO | Tiêu chuẩn SLA (Cam kết dịch vụ) |
| :--- | :--- | :--- | :--- |
| **Độ sẵn sàng dịch vụ (Availability)** | Toàn thời gian đợt mở cổng | $\ge 99.95\%$ | $\ge 99.9\%$ |
| **Tỉ lệ lỗi máy chủ (Error Rate)** | HTTP 5xx Status Codes | $\le 0.01\%$ | $\le 0.1\%$ |
| **Tính toàn vẹn dữ liệu (Data Integrity)** | Overselling (Bán vượt sĩ số) | **Tuyệt đối 0 trường hợp** | Không vượt quá sức chứa lớp |
| **Idempotency** | Trùng lặp lượt ghi danh | **0 bản ghi trùng lặp** | Unique constraint enforced |

## 2. Phân Tích Độ Trễ Theo Phân Vị (Latency Percentiles: p50, p90, p95, p99)

Độ trễ được tính từ thời điểm gói tin HTTP đi vào Nginx Reverse Proxy cho đến khi nhận được byte dữ liệu đầu tiên của phản hồi trả về trình duyệt.

```
                  ┌─────────────────────────────────────────────────────────────┐
                  │                   PHÂN BỐ ĐỘ TRỄ HỆ THỐNG                   │
                  ├───────────────────┬───────────────────┬─────────────────────┤
                  │ Phân vị (Metrics) │ Read API (ms)     │ Write API (ms)      │
                  ├───────────────────┼───────────────────┼─────────────────────┤
                  │ Median (p50)      │ 5 - 15 ms         │ 25 - 40 ms          │
                  │ 90th percentile   │ 30 - 50 ms        │ 80 - 120 ms         │
                  │ 95th percentile   │ <= 100 ms         │ <= 150 ms           │
                  │ 99th percentile   │ <= 200 ms         │ <= 250 ms           │
                  └───────────────────┴───────────────────┴─────────────────────┘
```

* **Lý do Write API đạt p95 $\le$ 150ms:**
  Lệnh `POST /api/v1/registrations` không chờ ghi đĩa PostgreSQL! Thay vào đó, API chỉ thực hiện:
  1. Kiểm tra JWT chữ ký trong bộ nhớ ($< 0.1\text{ms}$).
  2. Kiểm tra `X-Idempotency-Key` trên Redis ($< 1\text{ms}$).
  3. Chạy Redis Lua Script (Kiểm tra môn tiên quyết + Trùng lịch bitmap + Trần tín chỉ + Trừ slot) trong $< 2\text{ms}$.
  4. Đẩy payload vào RabbitMQ in-memory queue ($< 2\text{ms}$).
  5. Trả về mã phản hồi `202 Accepted` kèm `ticket_id`.

## 3. Thời Gian Phân Giải Kết Quả Bất Đồng Bộ (Async Persistence Time)
* **Luồng Controlled Short Polling:**
  * Sinh viên nhận `ticket_id` và tiến hành gọi `GET /api/v1/registrations/status/{ticket_id}` sau mỗi $1.0\text{s}$.
  * Worker mất từ $50\text{ms} - 300\text{ms}$ để đọc message, mở transaction và ghi vào PostgreSQL.
  * $95\%$ sinh viên nhận được trạng thái `CONFIRMED` ngay trong **lần polling đầu tiên** (sau 1.0 giây).
  * $99\%$ sinh viên hoàn tất xác nhận trong **lần polling thứ hai** (sau 2.0 giây).
