# 4.2 Chiến Lược Phân Tầng Bộ Nhớ Đệm (Redis Multi-Tier Caching & In-Memory Data Structures)

## 1. Cấu Trúc Khóa Trên Redis In-Memory

| Tên Khóa (Key Pattern) | Kiểu Dữ Liệu Redis | Mục Đích Sử Dụng | Thời Gian Sống (TTL) |
| :--- | :--- | :--- | :--- |
| `catalog:active_sections` | String (JSON Array) | Toàn bộ 200 lớp học phần phục vụ Client-side Search | 12 giờ |
| `section:{id}:slots` | String (Integer) | Số slot khả dụng hiện tại, trừ bằng lệnh `DECR` | Không TTL / Cố định |
| `section:{id}:enrolled` | Set | Tập hợp `student_id` đã giữ chỗ trong lớp | Không TTL / Cố định |
| `section:{id}:time_mask`| String (Bitmask) | Mặt nạ thời gian 84-bit của lớp | 12 giờ |
| `student:{id}:completed_courses` | Set | Danh sách mã môn sinh viên đã vượt qua | 12 giờ |
| `student:{id}:registered_slots` | Bitmap / Bitfield | 84-bit lịch học các môn đã đăng ký trong kỳ | Không TTL / Cố định |
| `student:{id}:credits` | Hash (`current`, `max`) | Số tín chỉ hiện tại và trần tín chỉ của sinh viên | Không TTL / Cố định |
| `ticket:{ticket_id}:status` | Hash (`status`, `reason`)| Trạng thái vé (`PENDING`, `CONFIRMED`, `FAILED`) | 30 phút |
| `idempotency:{key}` | String | Khóa chống trùng gói tin (`SET ... EX 60 NX`) | 60 giây |

## 2. Phòng Ngừa Cache Stampede (Warm-Up Pipeline)
* **Kịch bản Khởi động Lạnh (Cold Start Risk):** Nếu 3.000 sinh viên cùng truy cập lúc 08:00:00 mà Redis chưa có dữ liệu, 3.000 requests sẽ chọc thẳng vào PostgreSQL và làm sập cơ sở dữ liệu ngay lập tức.
* **Quy trình Khởi động (Pre-warming Pipeline):**
  * Script `scripts/warmup_cache.py` nạp trước toàn bộ dữ liệu từ DB vào Redis lúc $T-30$ phút.
  * Trong suốt đợt đăng ký, các khóa không đặt TTL ngắn để tránh hiện tượng rớt cache hàng loạt (Thundering Herd).
